## Deployment and readiness

Every Node runs IdP, Management and Storage with separate context data roots and one shared host `iroh-chain` endpoint/router with persisted endpoint identity and local trusted membership. There is no Storage-only, designated-authority or privileged-replica deployment mode. Keep Canonical Issuer/audiences separate from transport addresses and mount service prefixes once.

Create an Installation through restricted local setup with stable retry IDs and explicit initial administrator permissions. Join through a trusted reachable peer with authorized purpose-specific approval, approved endpoint/public signer binding, local secure signing capability and trusted shared state. Partial setup remains incomplete. After completion, trusted identity/policy and endpoint/completion state survive offline restart; readiness is not a 30-second lease and does not require the joining peer to remain reachable.

Authenticate owner-service calls even on loopback. Desktop uses one HTTPS listener, persistent port, explicit CA trust and certificate verification. Require TLS for remote HTTP. Secure-store/TLS failure stops setup/startup without plaintext fallback. Port conflicts must not silently change identity. Each Node owns and closes its endpoint once, and Storage denial must not erase independently authorized identity/join admission. Reuse `ofnet`'s endpoint/mesh/pairing/allowlist/generic connection-routing machinery; `of` owns trust decisions and domain/protocol adapter composition. See [networking ownership and source interfaces](design.md#networking-composition-and-trust).

## Current unified CLI provisioning boundary

The standalone `unified-server` CLI provides an **explicit restricted local** `provision` command. `serve` (including the implicit default) remains existing-only. A present local provisioning directory is authoritative: completed exact intent and current local readiness are required; missing, malformed or incomplete intent refuses without another startup path. When that directory is absent, an already explicitly provisioned host may start through public owner verification of its configured retained Node signer, matching persisted endpoint, retained context roots/databases and current local readiness. Retained nonsymlink context directories keep their existing permission contract, including a Storage root created as `0755` under an ordinary `0022` umask; this startup route neither applies the fresh owner-only directory policy nor changes permissions. The endpoint key must still be protected, and retained Storage `databases`/`filesystems` directories must exist. No journal is synthesized and no missing trust or identity is provisioned. This command creates a fresh Installation only; it is not a peer join, reset, migration, or a replacement for authenticated ongoing administration.

Configure the [unified example](../config/unified/example.yaml) before the first attempt: separate absent IdP/Management/Storage/endpoint roots, stable Canonical Issuer and public Application URIs, matching service audiences, and **four distinct canonical non-nil UUID Client IDs**. Supply distinct secrets through the deployment's secure environment injection using `UNIFIED_MANAGEMENT_IDP_CLIENT_SECRET`, `UNIFIED_STORAGE_IDP_CLIENT_SECRET`, `UNIFIED_STORAGE_MANAGEMENT_CLIENT_SECRET`, and `UNIFIED_IDP_MANAGEMENT_CLIENT_SECRET`. The fourth relationship remains optional for existing-host/library compositions, but the fresh local provisioning command and its journal continuation require it. Loading config/env alone is not authorization to provision. No command generates, logs, persists a raw-secret manifest, or rotates these relationship credentials on retry.

Deliver the initial password through an existing secure operator method into an operator-only regular file (`0600` or stricter), not a symlink. It must contain one nonempty UTF-8 line; a final LF/CRLF is removed. Do not put the password in argv, shell history, config, or logs. Password input remains operator-managed; retain secure access for retries and remove the temporary delivery file when no longer required. This command supports Unix permission checks only and fails unsupported rather than assuming Windows ACL protection.

From the repository/workspace build context with the sibling owner crates available:

```sh
cargo run --offline -p unified-server --features cli -- -c config/unified/example.yaml provision --fresh --administrator operator --node "Local Node" --password-file ./protected-initial-password
cargo run --offline -p unified-server --features cli -- -c config/unified/example.yaml provision --password-file ./protected-initial-password
cargo run --offline -p unified-server --features cli -- -c config/unified/example.yaml serve
```

The first command positively authorizes a new intent and requires all roots absent; the second is **exact continuation**, not another fresh declaration, and is unnecessary after an uninterrupted first success. Provisioning checks actual context composition/readiness, shuts down its validation runtime, durably records completion, and exits without leaving a server running. Serving is a separate operation. This existing unified listener is loopback HTTP; use a TLS-terminating reverse proxy for external exposure. These commands do not qualify the desktop HTTPS listener or OS credential-provider availability on a particular deployment.

Local state is retained beside the endpoint root: `endpoint_data_dir.with_extension("provisioning")`, e.g. `./data/unified/endpoint.provisioning`. `intent.json` retains the Installation/User/credential/Device-member/Node-key/role/permission IDs, issuer, roots, original names, ordered public Client requests, one-way credential verifiers, attempt disposition, public endpoint/signer identity, and explicit completion. Raw passwords, relationship secrets, private keys and tokens never enter this journal. The directory is `0700`, journal/lock files are `0600`, and publication syncs the file and directory ancestry before returning readback-verified success. Stable operator-controlled nonsymlink ancestry is required; these pathname checks do not defend against hostile concurrent ancestor replacement.

Retain `operation.lock` and its inode. The provisioner holds nonblocking local exclusion through setup and CLI serving; competing cooperating operations refuse rather than unlinking the lock. It does not coordinate arbitrary other hosts or generic owner callers against these roots. Do not delete journal, owner inventories, references, or context data to clear contention or manufacture freshness.

Before the first endpoint attempt or owner/private production, its exact intent and consumed attempt disposition are durable. Continuation opens the existing endpoint only, validates the same prepared User/ordered Client inventory, and uses public captured Client provisioning. First Node production is positively authorized once; later attempts use `verify_prepared_node_signer` before original enrollment, compare retained public identity, then require trusted `verify_node_signer` for readiness. The original pre-enrollment API blocker was fixed by approved owner delivery `b689241`; [historical blocker, owner handoff and current implementation evidence](../.scratch/offline-first-nodes/evidence/07-local-provisioning/README.md) distinguish that history from the present command.

Management initialization is durably marked attempted before calling the initial grant/Device-policy producers, and acknowledged only after both succeed. A never-started phase may initialize its absent root once. An attempted phase requires retained root/database; unacknowledged initialization requires explicit recovery even if the database remains. Acknowledged continuation never reruns those authority producers. Storage likewise retains its attempted root boundary, consumed only after listener binding succeeds and before runtime initialization. A bind-only failure leaves Storage genuinely never started. An attempted but unacknowledged Storage initialization requires explicit recovery; missing acknowledged `databases`/`filesystems` roots refuse before runtime construction. Journal fields are mandatory; incomplete shapes are denied, not migrated or defaulted.

A completed journal is historical evidence, not an authorization lease or sufficient current readiness. Startup verifies retained endpoint/signing capability, exact captured relationships and current local trust/context grants before serving. Failed or ambiguous first-write/store/readback attempts stay incomplete; missing attempted material requires exact recovery rather than regeneration. An interruption before a durable owner operation has actually begun can also conservatively require recovery once the host attempt is consumed. Retained owner-captured pre-enrollment signer material can be verified and reused even if its public return was not yet acknowledged in the host journal; the verifier supplies the exact owner-captured proof, not a new identity. No automatic reset or recovery command is supplied by this slice.

## Trust, partitions and revocation

At startup, `of` loads persisted locally trusted approved/non-revoked Installation Device endpoint membership into the shared `iroh-chain` allowlist and updates it as changes are learned. `EndpointIdStore` itself is in-memory, not a persistent trust store. Restore the endpoint key and owner trust state before ordinary protocol use without a live central lookup or expiry lease. Pairing exchanges are purpose-specific, not general access; connection/handshake allowlisting is not resource permission.

Use persistent trusted local IdP/Management state for authorization. Missing, invalid or locally revoked evidence denies the affected operation. Remote disconnection alone does not invalidate completed local trust. Any Node may mutate identity/policy/resources after its actor/action/target check.

A revocation/restriction becomes effective when a Node learns it. Verify denial of subsequent local operations, including on existing connections, and eventual propagation, not immediate global rejection on disconnected peers. Allowlist removal alone does not reauthorize those operations; `of` must retain execution-boundary checks. An already-authorized operation may finish. Previously copied bytes cannot be recalled. A Node learning transfer/deselection must gate affected local use until managed-copy cleanup or reset completes; an unaware offline Node can temporarily continue under its earlier view.

OAuth code consumption/refresh rotation is durable and atomic locally. Partitioned Nodes have no global single-use guarantee. Operators must not assume that reconnect reconciliation prevented earlier concurrent consumption or introduce a designated consumer to preserve the old role model.

## Secrets and local identity

Keep each Node's independent private signer local. Synchronize only explicitly approved public/other domain records; do not synchronize raw passwords, raw client secrets or private keys. Store secrets in the consuming service's supported OS keyring/deployment secure store. Protect local CA/server/private-signing key material with platform-equivalent owner-only permissions. Manifests contain IDs/references, not secrets. Never commit populated secrets or log tokens/credential bodies.

Existing ordinary service-client boundaries, where used locally, remain least-privilege:

| Caller → receiver    | Required scopes                                               | Audience boundary                                     |
| -------------------- | ------------------------------------------------------------- | ----------------------------------------------------- |
| Management → IdP     | `idp.token.validate`, `idp.device.lookup`                     | Configured IdP service audience                       |
| Storage → IdP        | `idp.token.validate`, `idp.device.lookup`, `idp.device.list`  | Configured IdP service audience                       |
| Storage → Management | `management.replication.read`, `management.replication.admit` | Configured Management Storage audience                |
| IdP → Management     | `management.permission.evaluate`                              | Management Application audience; registered evaluator |

Use distinct confidential clients/secrets per relationship and environment; never use User passwords for background service calls. Limit inspected-token audiences to caller needs. These local context calls must not introduce a live central authorization dependency. The explicit local CLI above captures all four exact relationships. IdP uses each Client's audience allowlist for both issuance and inspected-token validation: Management→IdP additionally lists `idp-management` and the configured Management Storage audience; Storage→IdP additionally lists the actual kind audiences `storage:databases` and `storage:filesystems`. Scopes stay restricted as in the table, and only the separately registered evaluator Client may assert a User for permission evaluation. These audience entries are not new User/resource grants or a global role.

Rotate through authorized local IdP operations, persist new consuming credentials securely, verify exact scopes/audiences and real owner calls, then revoke the old registration and remove old secret references. Test interrupted rollout and retry. A compromised client must be revoked locally and the change propagated; locally learned old credentials/tokens must fail appropriate activity checks. Other partitioned Nodes may not yet know the revocation. Never widen permission to mask a failed rollout.

## Persistence, reset and recovery

Persist context stores, endpoint identity and protected secrets for restart. `ofdb` owns SQL/KV sync/staging/batching/cleanup through public `ofdb-sql`/`ofdb-kv`; `offs` owns filesystem persistence/sync, not transport. `of` owns protocol-specific adapters wiring these owners to shared `ofnet` networking, not a second reusable networking stack. Mesh messages and direct Iroh streams are distinct; operations must not assume transparent multihop SQL/KV/filesystem synchronization. Do not run competing processes against the same local service roots or copy private signers to another Node.

Back up current-format local domain stores, endpoint identity and protected local secrets according to verified owner/platform procedures. Recovery restores that Node's trust and signing capability; it is not authority promotion and needs no live central service. No complete executable backup/recovery procedure is verified here. Invalid/incompatible state is preserved for explicit recovery/reset; do not silently delete or migrate it.

Reset removes only local setup/data/identity and can proceed offline. Attempt authorized revocation/propagation when possible. Secure-store deletion failure preserves remaining retry state. Deselect removes a local copy, not the global resource; deletion synchronizes a Tombstone. Passthrough content reads need an authorized reachable Full peer and cannot write.
