## What to build

Wire locally checked domain permissions before each actual apply operation using the generic owner execution hook. Question: can newly learned denial prevent the next mutation even after data was received, without cancelling an already-authorized operation?

## Scope and acceptance criteria

Qualification follows the [machine-local policy](../spec.md#machine-local-qualification-policy): real local owners and authenticated isolated same-host Iroh peers, with deterministic apply/write/revocation gates and focused Ubuntu checks. No remote physical machines, platform matrix or full feature/CRAP sweep is required. Prior resolved scope and evidence remain unchanged.

- [x] Identify actual SQL/KV apply operations, filesystem metadata/content mutations, API mutations, resource reads, and outbound/queued socket writes. Receiving, admission, and enqueueing do not authorize later execution.
- [x] Both peers independently check local trusted Device identity/owner, actor/action/target where applicable, subject/Application, resource kind/ID, both selections, and restrictions. Local identity comes from the injected endpoint; remote identity comes from authenticated Iroh, never handshake/header claims.
- [x] Supply authorization through generic owner execution hooks. No new trait is prescribed, and no IdP/Management policy enters `ofdb` or `offs`. Record the actual APIs and focused evidence from the linked ofdb 03/04 and offs 01 hook tickets. Native staging/composition and content-integrity prerequisites are already inherited through of 02. Do not block on ofdb 06 or offs 03 final status: supply this ticket's real authorization evidence to their handoff/acceptance work.
- [x] Distinguish `ofnet`/`iroh-chain` connection/handshake allowlist enforcement from `of` domain authorization. Bind the authenticated endpoint to a locally trusted Installation Device; pairing admission is not general access and membership admission is not resource permission. Use the shared endpoint and public owner hooks, not domain policy inside `ofnet` or a parallel networking layer. See [ownership/source interfaces](../../../docs/design.md#networking-composition-and-trust).
- [x] Learned revocation/restriction and failed local policy evaluation deny subsequent operations without applying them, including on already-open connections. Updating the endpoint allowlist is required for learned membership changes but does not replace execution checks or require a new handshake. Completed trusted local state authorizes offline operations; unreachable remote IdP/Management is not an authorization failure by itself.
- [x] An in-flight authorized operation may finish. Cancellation still releases streams/tasks/handles/staging through owner cleanup; preserve failed-batch rollback and earlier valid commits. Remove obsolete custom quota/timer/deadline and periodic authorization-polling wiring from `of`; do not replace it with new quotas, polling leases, timers or deadlines. Owner protocol integrity checks remain.
- [x] Deterministic real-owner/Iroh integration gates prove denial between receive/apply and enqueue/write, on both peers and all resource kinds. Explicitly observe the first KV batch commit before learning denial for a later batch; first commit and source data remain, denied later work is absent, reconnect succeeds when locally allowed.
- [x] Test authorized in-flight completion followed by next-operation denial on the same existing connection, failed local evaluation, forged endpoint/actor claims, pairing without resource access, allowlisted-but-unselected peers, and independent remote outage while local state remains valid. Keep transport-only/stub regressions separate from full acceptance.
