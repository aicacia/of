Status: claimed
Type: task

## What to build

Provide new-Installation setup and one equal-Node trusted-peer join path, with persistent local readiness and desktop setup/identity/Residency screens. Question: does a fully joined Node run all contexts and remain usable after restart with the joining peer disconnected?

## Scope and acceptance criteria

- [x] Remove Storage-only and privileged authority/replica role selection, readiness markers, and join flows. Every Node hosts IdP, Management, Storage; no role compatibility or promotion path remains.
- [x] Fresh setup uses restricted owner-local commands, stable IDs and exact retry verification, explicit initial administrator grants, and local secure storage. Do not restore unauthenticated setup mutations, password-grant join, mixed repositories, or wildcard future grants.
- [x] Join through any trusted reachable peer with authorized purpose-specific approval. Reuse `ofnet`/`iroh-chain` pairing offer/reply mechanics on the shared Node endpoint; `of` owns the approval decision and Installation, audience, actor permission, Device owner, endpoint and independent public signer binding. Pairing admission/exchange is not general access, resource permission, or Device approval by itself. Ordinary authentication alone cannot approve; no privileged machine is needed.
- [x] Persist approved/non-revoked Installation Device membership locally and load its endpoint IDs into the shared `iroh-chain` allowlist on startup, with no live peer/central lookup or trust-expiry lease. Apply locally learned approval/revocation updates to that set; untrusted discovery or pairing payloads cannot populate it. `EndpointIdStore` is in-memory, so `of` must supply durable owner state and restoration. See [source interfaces and ownership](../../../docs/design.md#networking-composition-and-trust).
- [x] Store private signer/secrets locally and synchronize only approved data. Readiness requires completed trust/state/signing stages, not expiring freshness or continued contact with the joining peer.
- [ ] Interrupt before/after every owner stage and secure-store write; resume with stable IDs, no duplicates, and no premature completion. Persist trusted state, policy, endpoint, local Device Setup completion and key references for offline restart.
- [ ] Corrupt/incompatible manifests and secure-store failures preserve retry state and report errors without plaintext fallback or silent deletion. Reset is explicit, local and offline-capable; failed secret deletion retains remaining retry state. Propagate authorized revocation later when possible.
- [ ] Desktop distinguishes incomplete setup, completed locally ready state, and unavailable peers without calling a completed offline Node unauthorized. Identity administration calls IdP directly; selections/Residency/completion use owner APIs and current prefixes. Incorporate cleanup gating from 05 before enabling transferred resources.
- [ ] Live desktop/keyring acceptance covers create/join, denied/forged approval, pairing without general access, interruption, retry, persisted allowlist restoration/update, peer disconnection, restart, reset, secure-store failure, and Full/Passthrough UI. Run existing Svelte analysis during future UI implementation and separate pre-existing errors.
