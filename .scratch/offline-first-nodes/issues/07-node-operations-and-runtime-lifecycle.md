- [ ] One Node host composes one shared `iroh-chain` endpoint/router, persisted endpoint key/identity and local trusted membership, with identity/bootstrap and Storage protocol adapters. Reuse `ofnet` endpoint/mesh/pairing/allowlist/generic connection-routing mechanics; `of` supplies Installation/Device trust, local authorization and protocol-specific wiring. No injected context creates/closes a second endpoint; Storage denial does not erase separately permitted join/identity admission. Audit current router helpers before assuming arbitrary handler registration. Background work starts after local readiness; focused tests prove managed listener/router/runtime shutdown and ordinary-error cleanup, without double-close or retained managed resources. Audit detached owner mesh work and record its lifecycle limitation/API follow-up explicitly; do not claim universal task joining.
- [ ] Load persisted locally trusted approved/non-revoked Device endpoint IDs into the shared allowlist before ordinary protocol use, restore them offline, and update them on learned membership changes. Missing/invalid trust denies; no central lookup or expiry lease. Handshake allowlisting is not resource authorization and pairing is not general access. Learned revocation must stop subsequent operations on existing connections through 03, not merely new handshakes. See [networking ownership/interfaces](../../../docs/design.md#networking-composition-and-trust).
- [ ] Desktop serves one HTTPS listener with prefixes once, stable port, explicit CA trust, certificate verification and secure key files. Occupied/invalid port, unsafe paths and TLS/secure-store failures stop startup clearly without fallback or new issuer/endpoint identity.
- [ ] Link actual local Linux secure-provider observations and verify Unix key/path protection and Installation-scoped naming independent of listener URLs. Use representative secure-store fault tests to prove fail-closed behavior. Scope provider availability to the exercised session; Windows ACLs, macOS keychain and unattended/headless access are deferred and must not be advertised as qualified.
- [ ] Verify the locally exercised Node configuration with all contexts, separate roots, stable issuer/audiences, explicit permissions, and supported secure secret references. Retain least-privilege distinct local service clients where used; remove centralized deployment roles and remote readiness/freshness dependencies.
- [ ] Prove representative authorized local same-ID Client secret rotation and registration revocation through real owner HTTP APIs, old-secret/current-activity denial and consumer reopen/retry without credential recreation. Audit all configured local relationship scopes/audiences and distinguish mock protected-provider evidence from actual secure delivery. Peer propagation belongs to08; interrupted multi-consumer delivery and deployment-specific rollout are follow-ups, not claims of instantaneous partitioned revocation or globally single-use grants.
- [ ] Validate the local host through changed-source runtime/binary checks and verify the sibling build-context/container recipe with available static checks. Image builds/runtime, TLS/Iroh reachability in containers and unattended credential persistence are deployment follow-ups, not substitutes for local evidence or closure gates. Any future image build requires capacity checks; no cache/data pruning is implicit.
- [ ] Test stopped current-format filesystem restore of all local context/endpoint/provisioning roots at the original paths on the same Node, retaining its protected provider/credentials. Verify identity, trusted signer, readiness and authenticated owner/consumer calls, plus invalid/missing-state denial without repair. Do not imply provider export/import, lost-provider, populated-content, stale-snapshot or crash-consistent recovery; those need separately qualified procedures. No migration, automatic reset, promotion, cloned signer or central authorization dependency.
- [ ] Use focused actual local TLS/runtime/owner regressions and available native evidence for listener lifecycle/reopen, port conflict, TLS failure, allowlist restoration/update, pairing isolation, admission independence, existing-connection learned denial and ordinary-error shutdown. Actual GUI/process exit is reported only when observed; callbacks/retained-handle tests qualify only their seams. Full-Node existing-connection composition belongs to08. Mesh messages and direct streams remain distinct; deployment guidance must not promise transparent multihop SQL/KV/filesystem sync. Replace historical operator commands only after current equivalents are verified; record gaps and evidence in named operations docs.
