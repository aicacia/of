Audit all configured local relationship scopes/audiences and distinguish mock protected-provider evidence from actual secure delivery. - [x] Validate the local host through changed-source runtime/binary checks and verify the sibling build-context/container recipe with available static checks. Image builds/runtime, TLS/Iroh reachability in containers and unattended credential persistence are deployment follow-ups, not substitutes for local evidence or closure gates. Any future image build requires capacity checks; no cache/data pruning is implicit.
- [x] Test stopped current-format filesystem restore of all local context/endpoint/provisioning roots at the original paths on the same Node, retaining its protected provider/credentials. Verify identity, trusted signer, readiness and authenticated owner/consumer calls, plus invalid/missing-state denial without repair. Do not imply provider export/import, lost-provider, populated-content, stale-snapshot or crash-consistent recovery; those need separately qualified procedures. No migration, automatic reset, promotion, cloned signer or central authorization dependency.
- [x] Use focused actual local TLS/runtime/owner regressions and available native evidence for listener lifecycle/reopen, port conflict, TLS failure, allowlist restoration/update, pairing isolation, admission independence, existing-connection learned denial and ordinary-error shutdown. Actual GUI/process exit is reported only when observed; callbacks/retained-handle tests qualify only their seams. Full-Node existing-connection composition belongs to08. Mesh messages and direct streams remain distinct; deployment guidance must not promise transparent multihop SQL/KV/filesystem sync. Replace historical operator commands only after current equivalents are verified; record gaps and evidence in named operations docs.
