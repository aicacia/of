## What to build

Complete locally checked Device mutation permissions, owner-bound selections, administrator restrictions, transfer and deselection orchestration. Question: can trusted local policy enforce exact ownership without remote lookups and safely retire managed copies when a change is learned?

## Scope and acceptance criteria

Qualification follows the [machine-local policy](../spec.md#machine-local-qualification-policy): focused Ubuntu owner/API/cleanup tests and isolated same-host authenticated peers. Representative deterministic transfer/cleanup/retry gates suffice; exhaustive platform/power-loss matrices and full feature/CRAP sweeps are not closure gates. Prior resolved scope and evidence remain unchanged.

- [x] Device enrollment/rename/approval/revocation enforce locally verified actor, exact action/target, and owner binding through IdP/Management owner boundaries. A generic User bearer or Storage read scope is insufficient; service principals cannot impersonate Users or gain pairing/admin capability accidentally.
- [x] Selection/deselection binds to trusted local IdP Device ownership, Installation, endpoint, and locally verified Storage kind/ID/namespace. A stale selection-policy owner cannot override IdP ownership. Unknown local resources deny; trusted local resources remain selectable offline. Keep resource-specific deselection and explicit permission checks.
- [x] Expose typed administrator restriction read/update APIs with exact scope/target permissions. Denied/malformed/wrong-target updates preserve prior policy; learned restrictions affect subsequent operations through 03.
- [x] Keep resource catalogs owned by `of`, IDs stable and distinct from names, namespaces `(subject, Application)`, and discovery distinct from content possession/access. Selections start empty; concurrent deselection wins, causally later selection may restore sync.
- [x] Transfer is authorized locally and records retry-safe completion. Once learned, clear old selections and runtime-managed copies before new-owner use/sync; interruption/cleanup failure keeps local use gated until completion/reset. An unaware partitioned Node may temporarily continue under old local policy; do not claim global offline blocking or remote erasure.
- [x] Deselect removes only the selected local copy, including covered locally created copies, via public owner cleanup APIs. Stop future access/work through open handles; preserve unrelated resources, source copies elsewhere, identity and Tombstones. No duplicate SQL/KV/filesystem cleanup implementation in `of`.
- [x] Preserve local Full/Passthrough semantics: remote content reads require an authorized reachable Full peer; Passthrough never writes. Generic removal/handle/persistence tests belong to external owners. Link the actual public cleanup APIs/evidence before closure; ofdb 02/05 and offs 02 establish stage/content cleanup and integrity, not automatically whole-resource managed-copy removal. Record any uncovered generic removal requirement as a specific owner follow-up, not an invented guarantee or blanket map blocker.
- [x] Real `of` owner API integration covers allowed/denied Device mutations, mismatched/stale owners, cross-namespace requests, restriction propagation, transfer/deselect during active use, cleanup failure/retry/restart, unaware partition then learned transfer, and new-owner gating. Regenerate contracts in 06.
